# FolderHub：本地文件夹导航中心

Windows 本地网页版文件夹快捷导航工具：用“模块 / 子模块”组织电脑上的科研、工作和开发文件夹，点击已关联的文件夹卡片即可通过**Windows 文件资源管理器**打开。**不会移动、重命名或删除真实文件。**

![Python](https://img.shields.io/badge/Python-3.10%2B-3776ab) ![Dependency](https://img.shields.io/badge/第三方依赖-零-success) ![Platform](https://img.shields.io/badge/Windows-10%2F11-blue)

## 快速启动

1. Windows 10/11 安装 Python 3.10 或更新版本（安装时勾选“Add Python to PATH”）。
2. 双击 `start_windows.bat`，或在命令行运行 `python app.py`。
3. 浏览器会自动打开 `http://127.0.0.1:8765/`。**不要关闭启动窗口**，窗口关闭时服务停止。
4. 点击“新建根模块”建立一级分类；通过普通模块继续嵌套，最末级使用叶子模块。
5. 创建叶子模块时点击“浏览...”选择已有本地文件夹（也可以粘贴绝对路径），保存后点击卡片即可在系统文件资源管理器中打开文件夹。

服务仅监听本机 `127.0.0.1`，不向局域网或互联网暴露端口。不调用云服务，也不会上传你的文件。

## 已实现功能

- **分类型无限层级目录树**：根模块只允许最顶层；普通模块可无限嵌套；叶子模块必须关联一个文件夹且不可再拥有子模块。左侧目录支持逐层展开/折叠并记住状态。
- **增删查改**：新增、修改名称、修改路径、调整父模块、删除当前模块及其子模块导航记录（**永不删除真实文件夹**）。
- **打开文件夹**：绑定了路径的卡片单击即可调用 `os.startfile()`，通过 Windows 系统 Shell 打开资源管理器；不存在的路径会提示错误。
- **文件夹选择**：通过 Python 标准库 tkinter 弹出 Windows 原生文件夹选择对话框。
- **收藏和全局搜索**：按模块名称、关联文件夹路径、完整所属分类路径搜索全部层级；显示结果归属层级；支持 `Ctrl+K` 聚焦搜索、收藏及网格/列表切换。
- **备份恢复**：通过 JSON 文件导出与恢复全部导航结构；恢复操作将**替换当前配置**，不会更改磁盘文件。
- **便携式持久化**：SQLite 默认保存在 `FolderHub/data/folderhub.db`，封面图片保存在 `FolderHub/uploads/`。两个目录已加入 `.gitignore`，绝不会因普通 `git add .` 被提交。首次启动会安全迁移旧 AppData 数据（详见下方）。

> 注意：浏览器安全机制不允许普通静态 HTML 直接打开 Windows 文件资源管理器，因此需要同时运行本地 Python 服务。不能将纯静态页面托管到 GitHub Pages 后实现本地文件夹打开功能。

## 常用启动命令

```powershell
# 在 FolderHub 目录内执行
python app.py                     # 默认 8765 端口，自动打开浏览器
python app.py --port 8770         # 指定其他端口
python app.py --no-browser        # 不自动打开浏览器
python app.py --data-dir "D:\FolderHubData"   # 自定义数据库及图片位置（图片在此目录下的 uploads/）
python -m unittest discover -s tests -t . -v  # 运行全部测试（当前目录必须是 FolderHub）
```

**测试目录说明（Windows / Git Bash / Python 3.15）：** `FolderHub/tests/__init__.py` 使测试目录成为可导入的包。执行命令前先确认当前目录；从项目仓库根目录（`DailyToolsSet`）测试时可以不切换工作目录：

```powershell
# 当前目录：D:\ChatGPT\DailyToolsSet
python -m unittest discover -s FolderHub/tests -t FolderHub -v
```

或者进入 `FolderHub` 后运行：

```powershell
cd D:\ChatGPT\DailyToolsSet\FolderHub
python -m unittest discover -s tests -t . -v
```

出现 `Start directory is not importable: 'tests'` 时，先确认 GitHub 最新代码已更新、`tests/__init__.py` 存在，以及 `-s` 指向真实的测试目录。该错误意味着**测试发现阶段失败，不是测试用例失败**。

自定义数据目录也支持环境变量 `FOLDERHUB_DATA_DIR`。首次使用 Windows 的文件夹浏览功能需要 Python 自带 tkinter（标准 Windows Python 安装一般包含）。

## 架构和安全边界

```text
FolderHub/
├── app.py                 # Python 标准库 HTTP + SQLite 后端
├── start_windows.bat      # Windows 一键启动
├── static/
│   ├── index.html         # 网页主界面
│   ├── styles.css         # 样式
│   ├── app.js             # 无依赖交互逻辑
│   └── favicon.svg
├── data/                   # 运行后自动生成，数据库（不上传 Git）
│   └── folderhub.db
├── uploads/                # 运行后自动生成，自定义封面（不上传 Git）
├── tests/
│   └── test_app.py        # 数据库和 HTTP 安全/CRUD 测试
├── .gitignore
└── README.md
```

HTTP 服务固定绑定 `127.0.0.1`；写入类请求需要动态令牌和 JSON Content-Type，并检验请求 Origin、Host，避免普通恶意网页直接发送文件夹打开请求。目录路径保存时要求绝对路径；实际打开时检查目录存在。服务不会执行用户输入的 shell 字符串。**此工具用于可信任的本机个人环境，不是可供外网部署的多用户文件管理服务器。**

## 首次上传 GitHub

如果远程仓库是空的，在**DailyToolsSet 仓库根目录**运行：

```bash
git init
git remote add origin https://github.com/CrazyA1ice/DailyToolsSet.git
git add .
git commit -m "feat: add FolderHub local folder dashboard"
git branch -M main
git push -u origin main
```

如果当前目录已经是 Git 仓库，**省略** `git init` 和 `git remote add origin`。如果报 `remote origin already exists`，可用 `git remote -v` 检查远端。`src refspec main does not match any` 常见于尚未创建首次 commit，或本地仍位于 `master` 分支；先 `git add .` 和 `git commit`，再 `git branch -M main` 后 push。

**不要把运行时数据库、私人路径备份文件或其他隐私文件上传到公开仓库。** Git 会忽略 `data/` 和 `uploads/`，但个人备份 JSON 若放在其他位置仍可能被 Git 跟踪，提交前请检查 `git status`。

## V1.1：开机启动、浏览器首页与换肤

### 开启 Windows 登录自启动

1. 正常运行 `start_windows.bat`，打开 FolderHub 页面。
2. 点击页面右上角 **「设置」**（也可点「换肤」），在“开机自启动”中打开开关。
3. 下次**登录 Windows 用户账户**后，系统将通过 `pythonw.exe` 静默启动本地服务，不会自动再打开一个浏览器窗口。
4. 关闭开关可删除相同启动项。关闭开关不会立即结束已经在运行的本地服务。

实现采用当前用户专属的注册表项 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`，仅添加或移除名为 `DailyToolsSet.FolderHub` 的值；**默认不开启，不修改其他启动项，也无需管理员权限**。这是登录后启动，而不是在操作系统未登录时作为 Windows 服务运行。需要完整 Windows Python 安装中包含 `pythonw.exe`，且安装位置及本工具 `FolderHub` 文件夹路径保持不变。移动文件夹或切换 Python 环境后，需重新打开开关以更新启动路径。建议将本工具放在稳定的本地目录，不要放在会被临时清理的路径。

如需使用命令行管理：

```powershell
# 在 FolderHub 目录内
python app.py --startup status
python app.py --startup enable
python app.py --startup disable
```

Windows 可在 **设置 → 应用 → 启动** 中查看启用情况。在某些系统配置下，安全软件或 Windows 的应用启动开关可能阻止已登记的应用真正运行。若正在运行 FolderHub，请不要重复启动服务（默认占用端口 8765）。

### 设为浏览器“启动时打开的页面”

请先启动 FolderHub、开启开机自启动，再将下面的网址设置为浏览器启动页：

```text
http://127.0.0.1:8765/
```

- **Google Chrome**：设置 → **启动时** → **打开特定网页或一组网页** → 添加新网页，填入上述地址。
- **Microsoft Edge**：设置 → **开始、主页和新建标签页** → **当 Edge 启动时** → 打开以下页面 → 添加新页面。
- 若仅想把它设为主页按钮跳转地址，可在浏览器“外观/主页按钮”中设置相同 URL。

**区别：**“启动时打开”不等于“每次新建标签页”。若要求每个新标签页都显示 FolderHub，通常需要浏览器扩展。本项目不为此添加扩展或修改浏览器策略。Windows 启动应用程序和浏览器启动进程顺序不受本工具控制，因此刚登录时可能短暂显示无法连接，此时刷新即可。

### 换肤

页面右上角的“换肤”可选择 **云白 / 午夜 / 雾森 / 暖沙 / 跟随系统**。主题标记保存在**当前浏览器的 localStorage**，不更改文件夹数据库，也不需要外网下载壁纸或 CSS。使用其他浏览器时需要单独设置。若清理浏览器站点数据，外观会恢复默认云白；文件导航数据仍存在 SQLite 中。

界面布局参考 [Homer Minimal](https://github.com/tchgrbr/homer-minimal) 的明晰卡片分组，以及 [Flame](https://github.com/pawelmalak/flame) 的浏览器起始页与主题配置理念；本项目未复制其源码或资产。整体仍由原生 HTML、CSS 和 JavaScript 构建，保持**零第三方依赖**。

### 排障提示

- 页面提示「无法连接」：确认 Python 服务已经运行，检查防火墙 / 是否误关闭启动窗口。仅绑定 `127.0.0.1`，无需放行局域网端口。
- 开机自启动不可用：确保安装的是 Windows Python 且存在 `pythonw.exe`，使用网页开关或 `python app.py --startup status` 查看状态。
- 已启动后重复运行提示 8765 端口被占用：说明可能有另一个 FolderHub 进程正在运行，直接打开网页即可。
- **本机安全**：自启动在后台运行的 Python 服务可触发打开系统资源管理器，因此仅供可信的个人 Windows 账户使用。不要部署到公网，也不要把真实路径的 JSON 备份上传公开仓库。


## V1.2：根模块、叶子模块、分层导航与全局搜索

| 类型 | 放置位置 | 能否继续建下级模块 | 绑定文件夹 |
| --- | --- | --- | --- |
| 根模块 | 只能在目录最顶层 | 可以 | 新创建时不允许；旧版已有绑定将被保留 |
| 普通模块 | 必须位于其他分类模块下 | 可以 | 新创建时不允许；旧版已有绑定将被保留 |
| 叶子模块 | 必须位于根模块或普通模块下 | **不可以** | **必须且仅能绑定一个文件夹** |

- 新建、编辑模块时可明确选择类型；修改为叶子模块前必须先移动或移除其全部下级模块。
- 左侧目录是可折叠树，点击小箭头展开/折叠，点击文字进入分类；点击叶子模块文字则调用 Windows 文件资源管理器打开关联目录。
- 页面全局搜索不受当前目录限制，支持多关键词搜索，并显示匹配结果完整上级分类；搜索范围为**导航模块名称和已登记路径，不会扫描磁盘内文件内容**。
- 第一次启动新版会在已有 SQLite 表上新增 `node_type` 字段，并推断旧记录类型：顶层为根模块、有子模块的为普通模块，其余已绑定文件夹的非顶层末级记录为叶子模块。旧版分类模块关联的历史文件夹路径不会被删除。
- 备份格式升级至 `version: 2`，仍可导入版本 1 的备份。建议升级前先使用页面的“备份”功能导出一份文件。
- 修改仅涉及 `FolderHub/` 目录，数据仍存储在 `%LOCALAPPDATA%\DailyToolsSet\FolderHub\folderhub.db`。


## V1.3：静默启动、资源管理器窗口前置与新视觉细节

### 真正静默的 Windows 开机启动

- 在网页设置里启用的登录自启动，仍使用 `pythonw.exe` + `--no-browser`，**不弹出命令提示符，也不主动打开网页**。登录系统时仅启动服务，浏览器启动页可以访问本机地址。
- **日常手动启动**：在 Windows 资源管理器里双击 `start_silent.pyw`。如果 Python 的 `.pyw` 文件关联正确，此操作也不显示控制台；若服务已经运行，会直接打开现有 FolderHub 首页。需要 Windows 标准 Python 安装及 pythonw.exe 文件关联。
- **查看错误、开发调试**：双击 `start_windows.bat`（会显示 CMD 窗口，这是正常的），便于看到异常日志；不要将它放入 Windows 启动文件夹。
- 若系统提示“选择打开方式”，可将 `.pyw` 文件的默认打开程序指定为 `pythonw.exe`（不是 `python.exe`）。
- 本机服务地址始终是 `http://127.0.0.1:8765/`，无外网依赖；Windows 登录自启动还是通过现有 HKCU Run 注册表项管理。

### 点击叶子模块时优先前置 Explorer

`explorer_window.py` 现在使用 `os.startfile` 调用系统资源管理器，然后通过 Windows `EnumWindows / SetWindowPos / SetForegroundWindow` 尝试定位并前置窗口。通过窗口标题匹配目标文件夹名，并优先新弹出的 Explorer 窗口；不会将其永久设为“始终置顶”，不会通过 shell 拼接执行用户路径。点击过程中页面会显示暂时的打开状态并避免重复点击。

**系统限制**：Windows 10/11 的焦点抢占保护、Explorer 复用现有标签页、重名文件夹或特殊窗口布局都可能令前置尝试失败/定位不精准；此时仍会正常打开原文件夹，但不能保证始终盖住浏览器。想验证请在 Windows 上将浏览器最大化，再点击叶子模块测试。测试环境无法运行 Windows GUI，因此需本机实测。

### UI 细节和可用性

在保留原生 HTML/CSS/JS（不增加 Node、npm 或云端资源）的前提下，参考 Homer 的卡片入口风格和 Dashy 的主题变量设计，进一步优化侧栏目录、卡片悬浮效果、顶部状态区、搜索框、留白和响应式布局。新增 **极光** 和 **石墨** 两种可持久保存的主题；保留此前所有主题、目录结构与 SQLite 数据。

- **外观配置**：七款主题（云白、午夜、雾森、极光、暖沙、石墨、跟随系统），五种强调色（蓝、紫、青绿、橙、玫红）。
- **布局配置**：舒适 / 紧凑密度，标准 / 加宽侧栏，自动 / 2 / 3 / 4 列卡片，页面介绍和统计区的独立显隐，单独的侧栏收起按钮。
- **设置面板分组**：“外观与布局”及“启动与首页”分开呈现，减轻滚动和查找负担。
- **设置持久化**：仅在当前浏览器 `localStorage` 的 `folderhub.appearance` 中保存显示参数；模块、层级、文件夹路径仍只由 SQLite 持久保存，既有数据不受影响。
- **本地运行**：不依赖 CDN，不需要联网，不新增 Python 第三方包。刷新页面后显示设置仍有效；换浏览器或清理浏览器站点数据后恢复默认外观。

**操作**：打开右上角「设置」，在“外观与布局”选项卡切换字号、主题、强调色、卡片列数等；点击顶部左侧的菜单按钮可收起或展开侧栏。`Ctrl + K` 仍然执行全局搜索。首页根模块、普通模块、叶子模块的结构规则及点击打开 Windows 文件资源管理器的行为保持不变。

**开发验证**：运行 `python -m unittest discover -s tests -v` 验证后端；使用 Chromium 模拟目录数据验证大屏页面、设置选项、侧栏收起和全局搜索。本环境不能直接浏览 `127.0.0.1`，因此浏览器测试使用内存里的模拟 API，不等同于 Windows 文件夹弹出与前台激活的实机验收。


## V1.6：自定义模块封面和预设图标

在根模块、普通模块或叶子模块的 **编辑模块** 窗口中，选择预设图标，或者点击 **上传封面** 从本机选择 PNG、JPG 或 WebP 图片（单张不超过 2 MB）。

- 首页根模块卡片上方显示封面，子模块卡片也支持；没有封面时显示由预设图标和渐变背景组成的默认图案。
- 左侧目录树显示对应的预设图标，保证小尺寸下仍清晰；自定义封面不会改变文件夹打开行为。
- 编辑窗口支持预览、替换和移除封面。**移除封面不会删除真实文件夹。**
- “设置 → 外观与布局 → 在模块卡片上显示封面图片”可全局控制显示，选择保存在浏览器；关闭仅隐藏，不删除图片。
- 图片保存在本机 SQLite 数据库的 `node_images` 表，支持通过 `/api/nodes/<id>/image` 在本机读取，不会上传外部服务器或 GitHub。
- JSON 备份升级到 **V3**：包含模块的预设图标、图片二进制的 Base64 编码。继续支持 V1/V2 老备份，原有数据迁移无需手动处理。
- 因图片加入备份，JSON 体积会增大；当前导入备份最大 32 MB，备份前可适当压缩图片。
- 出于安全考虑，不接受 SVG、远程图片 URL 或其他可能执行脚本的类型，仅允许匹配 PNG/JPG/WebP 签名的数据。

**提示：** 在公开仓库中只应提交代码，不应提交真实个人数据及包含图片/本机目录路径的 JSON 备份。

## V2.2：路径健康检查与批量路径前缀迁移

将 FolderHub 项目复制到另一台 Windows 电脑，或者更换硬盘盘符后，原本记录的绝对路径可能失效。本版本提供**手动检测与预览后更新**，只修改数据库中保存的文件夹导航地址，绝不移动真实目录。

1. 在网页点击 **设置 → 路径管理**，按需要点击「检查所有关联路径」。检测会逐一检查已绑定的文件夹是否可访问；不递归扫描目录，也不会自动修改任何路径。无权限、未连接网络共享盘和真实路径不存在都会列为「无法访问」。网络目录检查可能较慢。
2. 在同一页面填写「旧路径前缀」和「新路径前缀」，例如 `D:\Research` → `E:\Research`，或者 `D:\` → `E:\`。
3. 点击 **生成变更预览**。列表显示每个匹配模块的旧路径和新路径，自动排除类似 `D:\ResearchExtra` 这样的非子目录。
4. 确认无误后，点击 **确认并应用**，再次确认才会事务式修改所有匹配模块；如果预览后路径曾被其他操作修改，提交将被拒绝，并要求重新预览。
5. 再次点击「检查所有关联路径」核验。若盘符已经改变，先确认新磁盘/共享目录存在。本工具**不会替你创建或搬迁实际文件夹**。

**数据保护：** 请先到「数据与备份」保存一份完整 ZIP；原 SQLite 存储仍保留在 `data/`，封面图仍在 `uploads/`。仅 Windows 下提供本地可访问性检查；非 Windows 环境仍可预览路径替换。每次最多检查 1000 条路径或替换 1000 条匹配路径，超过上限时会中止并提示使用更精确的前缀。本功能不会上传你的目录信息至云端。

**开发验证：** `python -m unittest discover -s tests -v`；新测试覆盖大小写与目录边界、UNC 路径、过期预览、事务回滚、鉴权及非递归可访问性检查。实际 Windows 盘符和网络共享行为仍需在用户设备上验证。

## V4.0：智能路径迁移建议（只读辅助）

换电脑、更换盘符、重新整理项目根目录后，若不知道旧目录层级从哪里开始替换，可在「设置 → 路径管理 → 智能迁移建议」输入一个**已存在的新根目录**（如 `E:\Research`），点击「分析可能的迁移规则」。

- 后端仅从最多 1000 条已经保存的导航路径中提取候选旧前缀，最多评估 12 组旧前缀，每组抽样最多 24 个目标目录，按可访问数量排序并展示最多 5 条建议；只检查给定路径本身是否存在，不遍历文件，也不自动扫描其他磁盘。
- 每条建议显示涉及的导航模块数量、实际抽样数量和抽样中可访问的路径数量。**抽样证据不等于全部目录已迁移**：如果存在新目录不可访问或原目录仍有效等情况，不应直接确认批量改写。
- 点击「采用并生成预览」，仅将旧/新前缀填入原来的迁移表单并调用现有只读预览。需要再次人工核对完整旧/新目录清单、点击「确认并应用」、确认弹窗后，才会通过事务修改 SQLite 中的导航记录。预览过期或记录变化仍然阻止应用。
- 输入变更、单项模块编辑、批量迁移成功后会清除过期建议；网络共享目录可能较慢，建议先在本地磁盘测试。工具不会移动、复制、删除真实文件或将路径上传至云端。
- 非 Windows 系统下，可通过注入文件存在性回调测试推断逻辑；实际目录检查须在 Windows 本机完成。新增路径推断、接口鉴权、UNC 路径、无证据拒绝和抽样上限等回归测试。


## V4.1：项目工作区（与文件夹工作组区分）

**项目工作区用于集中浏览、记录项目说明和管理关联模块**，不是「文件夹工作组」的一键打开多个资源管理器窗口。

- 左侧侧栏「项目工作区」旁点击 `＋`，填写名称（1—40 字）、项目说明（最多 240 字）并勾选 1—30 个现有导航模块；支持搜索模块名称、路径和所属分类。也可先在主页面「多选」模块，再点击「保存为工作区」快速预填成员。
- 工作区支持根模块、普通模块和叶子文件夹混合关联；进入后显示已选择的模块卡片，可逐个浏览、编辑或打开对应目录。工作区自身**不会批量打开文件夹**。成员顺序按选定记录保留；既有模块删除后显示失效数量，可在编辑窗口取消失效引用。

- 工作区只保存已存在模块的 **ID**，不在工作区记录中复制绝对路径；最多 20 个工作区，单个最多 30 个成员，名称不能重复。服务端严格检验字段、ID 类型、重复 ID 和控制字符，非法修改不覆盖已有配置。
- 工作区写入 `data/preferences.json`，与个性化设置、工作组、智能收藏夹一起包含在完整 ZIP 便携备份中。普通导航 JSON 备份仍只含导航结构，不含工作区。旧配置无需手工迁移，缺少工作区字段时默认为空列表。
- 回归测试涵盖配置持久化、完整 ZIP 备份、无效数据原子拒绝、默认可变对象隔离、工作区侧栏/编辑/路由前端契约。Windows 验收在仓库根目录执行 `python -m unittest discover -s FolderHub/tests -t FolderHub -v`。

## V4.5：多标签页配置冲突保护与保存队列可靠性

原来的 `PUT /api/preferences` 会覆盖整份 `data/preferences.json`。两个浏览器标签页同时打开时，后保存的旧快照可能清除另一个标签页刚刚改好的项目工作区、标签筛选和外观设置。本版本增加了**乐观并发修订号**以防止这种意外覆盖。

- `GET /api/preferences` 响应增加 `revision` 字段：尚未保存配置时为 `null`，否则为当前配置内容的 `sha256:` 修订标识。首次 `POST` 初始化和后续 `PUT` 也返回新修订号；旧请求仍可省略该字段以兼容既有 API 调用。
- 新版浏览器客户端每次 `PUT` 都同时发送 `expected_revision`。服务端在同一个偏好存储锁下读当前文件并核对版本，若与浏览器持有的版本不同，返回 **HTTP 409** 与 `code=preferences_conflict`，不修改任何配置文件。版本字段格式不合法返回400。
- 同一标签页快速连续修改会按顺序依次持久化，并在成功后使用最新返回的修订号。发生版本冲突、网络中断或其他保存失败时，**停止后续队列写入**。浏览器提示记录尚未保存的草稿后手动刷新；不会自动刷新而清空正在编辑的输入内容。重新打开页面会读取当前服务端版本。
- 完整 ZIP 备份与原来的 SQLite 结构保持不变，不包含任何新的用户项目数据字段。修订号是配置内容的派生标识，不是用户身份验证令牌，不要将其当作授权依据。
- **范围说明：** 冲突保护针对连接到同一个 FolderHub 本地服务实例的多个浏览器标签页；外部旧客户端若故意省略 `expected_revision` 仍可以覆盖配置。多服务进程同时写同一配置文件的操作系统级文件锁不在本轮实现范围内。
- 回归覆盖：修订号稳定性、首次写入、两标签页冲突原子拒绝、HTTP 409 / 400、页面保存队列静态契约及 JavaScript 成功/冲突/网络错误的模拟运行。请在 Windows 中运行完整 `unittest` 测试以验收。


## V4.6：Windows 全局快捷菜单（无第三方依赖）

FolderHub 现在可以在**托盘程序运行期间**按 **Ctrl + Alt + Shift + F**，在鼠标当前位置打开原生 Windows 快捷导航菜单。不需要先切到浏览器；该快捷键通过 Win32 `RegisterHotKey` 注册，而非网页内快捷键。

- 菜单分别显示**最多8个收藏目录、8个最近访问目录、8个项目工作区**。收藏和最近列表会去重；无可用资源时仍提供「打开完整工作台」。目录名称中的 `&` 等会被处理为普通显示字符，不作为意外的系统菜单快捷键。
- 选择收藏或最近目录时，托盘使用现有 `POST /api/nodes/<id>/open` 接口，携带本机服务的授权令牌，由服务端重新验证模块绑定目录并记录正常打开次数；不会执行用户提供的任意路径、Shell 命令或程序。选择工作区仅打开原有 `#workspace/...` 网页入口。
- **启动方式：** 双击 Windows 上的 `start_silent.pyw`，或通过此前设置的 Windows 登录自启动运行托盘。也可使用 `python tray.py` 进行控制台调试。仅运行 `python app.py` 或 `start_windows.bat` 不会注册全局快捷键，需要另行运行托盘；若托盘发现独立服务已启动，它只附着入口，不关闭独立服务。
- 托盘右键菜单也提供「快捷导航」，所以快捷键冲突时仍可使用。若系统或其他程序已占用 Ctrl+Alt+Shift+F，注册失败不会阻止原有托盘或服务启动。此版本的组合键为**固定值**，尚不提供用户自定义；关闭托盘时会注销全局热键。
- 若已运行旧版托盘，`git pull` 后需要**退出旧版托盘并重新启动**才能注册新快捷键。重启后台托盘会短暂停止它管理的本地服务，请先保存页面上的编辑内容。
- 快捷菜单只使用 FolderHub 已有的导航记录、最近访问数据和工作区配置，不扫描整块磁盘，不访问公网，不引入额外 Python 依赖。连接的是独立运行的 FolderHub 服务时，菜单通过本机只读接口取得内容；不会强行接管或重启独立服务。
- 新增托盘模块的跨平台纯函数及模拟 Win32 菜单单测。**Windows 热键实际注册、用户桌面位置和系统菜单显示效果**仍需在 Windows 实机验收；运行 `python -m unittest discover -s FolderHub/tests -t FolderHub -v` 可以完成自动化回归。


## V4.7：Windows 资源管理器当前目录快速收藏

**只在 FolderHub Windows 托盘程序运行时**，切换到目标文件夹所在的**资源管理器窗口**，按 **Ctrl + Alt + Shift + A**，即可尝试读取当前窗口所代表的真实文件系统目录。程序先弹出**完整路径确认框**；核对与资源管理器当前标签页完全一致后，选择「是」才会在 FolderHub 中保存快捷导航。

- 若目录已存在于 FolderHub 导航树，**不新建副本、不移动原节点**，仅把原模块设为收藏。若此前没有该目录，将自动建立顶层分类「快速收藏」，并在分类下新增一个已收藏的叶子模块。操作只修改 FolderHub SQLite 导航记录，不修改真实文件夹。
- 后端新增经过认证的 `POST /api/quick-capture`，校验真实目录必须存在，通过单次数据库事务保证创建分类与叶子模块的原子性，避免中途失败留下空分类。重复提交相同路径会复用已有模块。没有管理员权限要求。
- 检测方法使用 Python 标准库调用内置 **Windows PowerShell** 的 `Shell.Application.Windows()`，并且只匹配按快捷键时**前台资源管理器窗口的 HWND**。启动 PowerShell 最多等待7秒。没有在脚本中拼接用户输入的路径，也不会执行收藏目录内的文件。
- **Windows 11 标签页限制：** Windows Shell COM 对多标签页的窗口/标签匹配可能不一致，因此本功能不会静默收藏：必须核对确认框显示的完整路径；若不是当前标签页，请选择「否」，将目标目录打开为独立资源管理器窗口后重试。虚拟文件夹（如“此电脑”）以及无法确定真实文件系统路径的窗口不会收藏。
- 如果已占用 **Ctrl + Alt + Shift + A**，该快捷键无法注册，但普通导航快捷键 **Ctrl + Alt + Shift + F**、托盘和网页仍然可用。关闭托盘时两个快捷键都会注销。仅独立运行 `python app.py` 不会注册全局快捷键，需运行 `python tray.py` 或 `start_silent.pyw`。
- 快速收藏之后，已打开的 FolderHub 网页可能需要手动刷新才会显示新模块。该功能默认放在「快速收藏」分类，不会自动选择任意现有项目工作区。
- 自动化测试覆盖重复路径、收藏已有节点、失效目录、HTTP访问授权、PowerShell路径识别模拟、确认取消与快捷键清理；真实 Windows 资源管理器（特别是 Windows 11 多标签页）的行为仍需在本机验收。


## V4.8：单一全局快捷键与轻量化导航

本版按实际使用反馈简化入口，不再叠加独立的快捷键或统计栏目。

- **只注册一个全局快捷键。** 默认 **Ctrl+Alt+Shift+F**；右键 Windows 系统托盘图标 → **设置全局快捷键…**，可从五种组合中选择：Ctrl+Alt+Shift+F、Ctrl+Alt+Shift+Q、Ctrl+Alt+Shift+S、Ctrl+Shift+F、Ctrl+Alt+Space。配置以原子方式保存在忽略 Git 追踪的本地 `data/hotkey.json`，修改后立即尝试切换；如果 Windows 拒绝注册新组合，会尝试恢复原快捷键。当前支持这些常用预设，不是自由输入任意按键。
- **单次按键弹出功能列表：** 文件夹导航（最多8项）、项目工作区（最多8项）、**收藏当前资源管理器目录**、打开完整工作台。选择“收藏当前目录”后才执行窗口路径识别和确认；无额外快捷键。由于原生弹出菜单本身可能获得焦点，菜单打开前先记住前台窗口句柄。
- **快速收藏确认框强制置顶。** 使用 Windows `MB_TOPMOST | MB_SETFOREGROUND` 和默认“否”按钮，即使浏览器或资源管理器在前也应显示在最上方。Windows 11 多标签页仍可能返回不同标签路径，操作前务必核对完整路径；不一致时选“否”。
- **精简界面：** 从左侧导航移除“我的收藏”“最近使用”“常用文件夹”“回收站”四个入口；卡片不再显示星标、置顶或额外收藏按钮；模块编辑和批量操作也不再显示收藏字段。启动只请求 `/api/nodes`，不再并行请求三类用量/回收站接口；快速搜索只使用内存里的导航数据，减轻初始加载和点击打开的额外请求。
- **目录快速收录：** 发现已有路径时直接复用已有模块；新目录放入“快速收录”根分类。不再自动设置旧版星标字段。旧名称为“快速收藏”的分类及历史导航数据不会被自动改名、删除或迁移，以免意外损坏用户资料。
- **数据处理原则：** 原有回收站、用量记录和收藏标记仅不再出现在主要界面；其数据及兼容接口暂时保留，以保障旧版备份与误操作恢复的安全。**这不是物理删除历史数据库**。如需彻底清理历史记录，应先完成便携备份，并在后续版本提供独立迁移流程。
- **保留的快捷搜索：** 网页内部 Ctrl+Shift+P 的“快速打开模块”属于页面内快捷操作，不注册 Windows 全局热键。托盘退出时会注销唯一的 Windows 全局热键。
- 仍需 Windows 实测：快捷键切换后旧组合是否释放、冲突时的恢复、菜单选择快速收藏后的路径确认、置顶弹窗在多显示器和资源管理器标签页场景下的行为。
